# 执行器

Executor 是真正在工作区内改文件、跑命令、跑测试的本地 Coding Agent。**当前只有 OpenCode 会真正启动**；`codex`、`claude` 仅可登记与探测。

## 抽象与注册表

执行器通过统一的 `Executor` trait 与核心解耦（`src/core/executor.rs`）：

```text
trait Executor {
  id() / kind() / name()
  detect() -> PathBuf
  start_task(plan, AgentContext, workspace, proxy) -> SpawnedTask
}
```

`ExecutorRegistry` 统一加载执行器、代理与默认代理：

- 从 SQLite 读取执行器定义，仅 `kind == "opencode"` 会实例化为 `OpenCodeExecutor`。
- 支持按 id、按小写名称、以及 `opencode` 别名查找。
- 若 SQLite 未配置 OpenCode，则回退到 `config.toml` 的 `[executor]`。
- 白名单 `opencode` / `codex` / `claude`；`validate_executor_type` 对非 OpenCode 返回 `TypeNotImplemented`，注册表会跳过。

执行器命令来自本机配置（Web 控制平面 / SQLite），**MCP 请求不能指定可执行文件或 shell 命令**。

## Proxy 路由

每个执行器可绑定 `proxy_id`，解析规则（`resolve_proxy_for`）：

| `proxy_id` | 行为 |
| --- | --- |
| `None` / 空串 / `"none"` | 直连（不走代理） |
| `"default"` | 使用默认代理（若已启用） |
| 具体 id | 精确匹配该代理（若已启用） |

默认代理优先取 SQLite 中 `is_default && enabled` 的代理，否则回退到 `config.toml` 的 `[proxy]`。命中代理时，会向 Executor 子进程注入：

```text
HTTP_PROXY / HTTPS_PROXY / ALL_PROXY = <proxy url>
NO_PROXY = localhost,127.0.0.1,::1
```

代理支持 `http` / `https` / `socks5`（socks5 与 socks5h 统一按 `socks5h://` 输出）。

## OpenCode 执行

一次任务闭环：

1. Brain 通过只读 MCP 工具检查仓库。
2. Brain 调用 `task_start`，传入 `goal` 与 `plan.actions` / `tests` / `success_criteria`。
3. AgentBridge 写入任务交接快照 `~/.agentbridge/handoff/<task_id>.c2c`（非权威，权威状态在 SQLite），并添加 `AgentContext`。
4. 在所选项目目录内启动：

   ```text
   {opencode} run --auto "Read <absolute handoff path> and implement that PLAN. ..."
   ```

   - `current_dir` 为项目根目录。
   - 参数以结构化 argv 传入（单行提示词，适配 Windows `.cmd` 包装器）。
   - 独立进程组（Windows `CREATE_NEW_PROCESS_GROUP`，Unix `process_group(0)`）。
   - 清除子进程环境中的 `AGENTBRIDGE_AUTH_TOKEN`。
5. 捕获退出码、简短摘要、测试摘录与变更文件；`<think>` 等推理内容被剥离。
6. Brain 轮询 `task_status`，随后读取 `git_diff`、`test_status`、`execution_summary`。
7. Brain 给出 REVIEW：DONE、再次 PLAN，或 BLOCKED。

## 输出处理

- 每个标准流最多捕获 64 KiB；`stream` 模式可实时转发，`silent` 模式静默。
- `strip_reasoning` 丢弃 `<think>` / `<thinking>` 块，以及 JSON 事件中 `thinking` / `reasoning` / `think` / `internal` / `thought` 类型，并抽取 `text` / `response` / `part.text`。
- `extract_tests_excerpt` 提取至多 8 行测试相关输出。
- 摘要截断到 2000 字符。

## 进程与取消

- `find_executable` 在 Windows 优先匹配 `PATHEXT`（`.exe/.cmd/.bat`）。
- `kill_process_tree`：Windows 使用 `taskkill /T /F`，Unix 使用进程组 TERM。
- 取消通过 `CancellationToken` + 终止进程树实现，`task_cancel` 安全终止整个进程树。
- 每个项目同时只允许一个活动任务（内存 mutex + `executor.pid` 双重校验）；不同项目可并发。

## 登记与探测

- `GET /api/executors` 列出执行器并探测可用性（executable / version / status）。
- `POST /api/executors/{id}/test` 做连通性测试。
- `GET /api/executors/available` 返回当前真正可实例化的执行器（目前仅 `opencode`）。
- Web **执行器** 页面支持登记（当前表单固定 `opencode`）、列表、测试与删除，见 [Web管理](Web管理.md)。

## CLI（可选，使用同一个执行器）

```bash
agentbridge task start --goal "Create TEST.md" --tests "cargo test" --execute
agentbridge task status
agentbridge task cancel
```

带 `--execute` 会前台启动 OpenCode 并等待；不带时只写入 PLAN（适合自行运行 OpenCode 的场景）。手动回填结果：

```bash
agentbridge task executed --status success --tests "cargo test" --exit-code 0
```

## 诊断

`agentbridge doctor` 会报告 OpenCode 是否安装、版本探测结果，以及 config / workspace / port / bind / auth / git / cloudflared 的状态。

## 安全

- Executor 的 cwd 是所选项目目录。
- MCP 不能选择可执行文件或 shell 命令。
- 公网 MCP URL 必须启用 OAuth 2.1（或 `--auth-token`）。
- AgentBridge 不对 Executor 施加 OS 沙箱；它是用户已信任的本地进程。
