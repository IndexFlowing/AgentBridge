# AgentBridge 后续开发待办与路线图

> 当前版本：**1.0.4**
>
> 本文用于记录 AgentBridge 后续演进方向，避免功能开发过程中遗忘已经确定的设计。
>
> 原则：**CLI/Core 是产品主体，MCP 是 AI 控制入口，Web 是管理工具。**
>
> 当前阶段优先保证核心服务稳定、可运行、可管理，再逐步完善高级能力。

------

## 一、产品架构原则

AgentBridge 的核心定位：

> 将远程 AI Brain 与本地 Coding Agent 安全连接起来。

整体结构：

```text
                    Brain
                      │
                      │ MCP
                      ▼
             ┌─────────────────┐
             │   AgentBridge   │
             │                 │
             │ CLI             │ ← 主控制面
             │ MCP             │ ← AI 控制面
             │ Web             │ ← 管理面
             │                 │
             │ Project Manager │
             │ Task Runtime    │
             │ Executor        │
             │ Provider        │
             │ Proxy           │
             │ Storage         │
             │ Security        │
             └────────┬────────┘
                      │
                Local Executor
                      │
                   OpenCode
                      │
                 Workspace
```

### 核心原则

1. CLI/Core 是真正的产品主体。
2. `agentbridge start/stop/restart/status` 等能力必须能够独立工作。
3. Web 不应该拥有独立于 Core 的业务逻辑。
4. Web 只是 Core 的管理和可视化界面。
5. MCP 是 AI Brain 与本地 AgentBridge 通信的主要入口。
6. SQLite 保存运行数据和动态配置。
7. `config.toml` 保存启动级配置。
8. Service Lifecycle 与 Executor Process Lifecycle 必须严格分离。
9. 高级功能必须建立在稳定的 Core 之上。

------

# 二、P0 —— 基础稳定性

P0 是当前最高优先级。

## P0-1 Service Lifecycle

目标：让 AgentBridge 成为真正可以长期运行的本地基础设施服务。

需要支持：

```text
agentbridge start
agentbridge stop
agentbridge restart
agentbridge status
```

要求：

- 防止重复启动。
- stop 未运行时安全返回。
- status 能准确判断运行状态。
- PID 管理可靠。
- 不能误杀其他进程。
- Server PID 与 Executor PID 严格分离。
- `serve` 作为底层前台运行入口。
- 生命周期状态不能依赖 SQLite。
- 为未来 Windows Service / Linux systemd / macOS launchd 保留扩展边界。

------

## P0-2 Config

`config.toml` 是启动级配置的唯一 Source of Truth。

默认：

```toml
[server]
host = "127.0.0.1"
port = 8040

[mcp]
auth_token = "agentbridge"

[logging]
level = "info"
```

原则：

- 默认端口：8040。
- 默认 host：127.0.0.1。
- `allow_any_host` 默认 `true`。
- 不因为 `allow_any_host=true` 擅自把 host 改成 `0.0.0.0`。
- 启动配置不能依赖 SQLite。
- 首次启动自动创建默认 config。
- 修改启动配置后通过 restart 生效。
- 版本始终以 Cargo.toml 为准，目前为 1.0.4。

------

## P0-3 Core 稳定性

在继续扩展功能之前，确保：

```text
cargo fmt --check
cargo check --all-targets
cargo test
cargo diff --check
```

以及实际运行：

```text
agentbridge start
agentbridge status
agentbridge stop
agentbridge status
agentbridge restart
agentbridge status
```

并完整验证 MCP。

# 三、P1 —— Web 管理后台整体重构

当前 Web 界面已经基本处于不可用状态。

**不要继续采用“哪里不好修哪里”的方式。**

应该进行一次完整的 Web 架构和 UI 重构。

## Web 定位

Web = AgentBridge Management Console。

它不是 AgentBridge 的核心运行环境。

所有业务逻辑必须来自 Core/API，Web 负责：

- 查看状态
- 修改配置
- 管理资源
- 查看任务
- 查看日志
- 可视化运行状态

# 五、P1 —— Proxy Manager

国内使用部分 AI Provider 时需要代理，因此 Proxy 是核心能力，而不是附属功能。

支持：

```text
None
Default
Specific Proxy
```

例如：

```text
OpenCode → Clash
Claude   → Clash
Gemini   → SOCKS
DeepSeek → None
```

Proxy Manager 支持：

- 多代理
- HTTP
- HTTPS
- SOCKS5
- SOCKS5H
- Host
- Port
- Username
- Password
- Enable / Disable
- Default Proxy
- Proxy Test

Proxy 数据适合放 SQLite。

Proxy 与 Provider / Executor 解耦。

# 十一、P2 —— Task Execution State / Progress

这是已经确定的后续重要能力。

目前 AgentBridge 有 Task Status，但还没有真正意义上的任务进度模型。

未来 TaskRuntime 应成为唯一状态来源。

建议状态：

```text
Queued
  ↓
Planning
  ↓
Preparing
  ↓
Executing
  ↓
Testing
  ↓
Reviewing
  ↓
Completed
```

建议字段：

```text
stage
progress
message
started_at
finished_at
iteration
```

原则：

**不要简单根据执行时间计算百分比。**

进度应该基于实际可观察状态。

例如：

```text
Testing

cargo test
54 / 72

███████████████░░░░░ 75%
```

### CLI

```text
Task: abc123
Status: RUNNING
Stage: TESTING
Progress: ███████████████░░░░░ 75%
Message: cargo test 54/72
```

### MCP

`task_status` 返回结构化执行状态。

### Web

显示：

- Progress Bar
- Stage Timeline
- Current Message
- Iteration
- Changed Files
- Tests

这是未来实现 Web 实时任务体验的重要基础。

# 十五、P3 —— Skill Manager

Skill 暂时不实现。

这是后期能力。

目标：

```text
Global Skills
Project Skills
Task Skills
```

Skill 最终应该进入：

```text
task_start
    ↓
SkillResolver
    ↓
Executor
```

而不是只做一个 Web Skill 文件管理器。

核心目标：

> 让 Executor 在执行任务时主动遵循项目架构、Rust、重构、测试、安全等规范。

避免 AI 长期在一个文件中不断追加代码而不重构。

未来目录方向：

```text
src/skill/
├── mod.rs
├── manager.rs
├── loader.rs
├── resolver.rs
├── parser.rs
└── models.rs
```

建议 Skill 内容以文件/Git 为主，SQLite 保存 metadata。

# 十八、开发原则

### 原则 1：先稳定，再扩展

不要在基础设施还不稳定时同时开发大量高级功能。

### 原则 2：Core First

任何能力首先应该存在于 Core。

CLI 是第一控制面。

Web 只是第二种操作方式。

### 原则 3：不要复制业务逻辑

```text
CLI ──┐
MCP ──┼──> Core
Web ──┘
```

而不是：

```text
CLI → 一套逻辑
Web → 一套逻辑
MCP → 一套逻辑
```

### 原则 4：配置职责清晰

```text
config.toml
    ↓
启动级配置

SQLite
    ↓
运行数据 / 动态管理数据

.agentbridge/
    ↓
当前执行上下文
```

### 原则 5：小批次开发

每次只完成一个明确阶段。

完成：

```text
实现
 ↓
测试
 ↓
实际运行
 ↓
验收
 ↓
下一阶段
```

不要一次性大规模修改整个项目。
