# 架构

AgentBridge 是一个本地常驻进程，而不是一个 Coding Agent。它连接两端的 AI 角色（Brain 与 Executor），并在本地托管工作区、任务、Agent 配置与认证。

本文描述当前代码实际落地的架构。**CLI / Core 是主接口，Web 是管理控制面，Desktop / Tray 已废弃。**

## 总览

```text
                    Brain (远端 AI)
        ┌───────────────┼───────────────┐
        │               │               │
     Gemini          Claude         ChatGPT
        │               │               │
        └───────────────┼───────────────┘
                        │  MCP (Streamable HTTP)
                   只读检查 + task_start
                        │
                 ┌──────▼──────┐
                 │ AgentBridge │  Rust Core + CLI
                 │  + Web 管理 │  （同一进程）
                 └──────┬──────┘
                        │  C2C PLAN + AgentContext
                        ▼
                   Executor（当前仅 OpenCode）
                        │
               编辑 / 运行 / 测试
                        │
                        ▼
                 本地项目工作区
                        │
         git_diff / test_status / execution_summary
                        │
                        ▼
                    Brain 审查
```

## 代码分层

代码遵循「适配器 → 领域能力 → 基础设施」的单向依赖，组合根为 `AppCore`（`src/core/context.rs`）。

| 层 | 位置 | 职责 |
| --- | --- | --- |
| **adapters（适配器）** | `src/adapters/` | 对外接口：CLI、MCP Server、OAuth、HTTP/Web、管理 API。只做协议转换与调用 Core，不承载业务逻辑 |
| **core（领域能力）** | `src/core/` | 业务能力：Project、Task、Executor、Agent、Skill、Provider、Workspace、Protocol |
| **infra（基础设施）** | `src/infra/` | 基础实现：SQLite Storage、config.toml 配置、daemon 生命周期、通知 |

`AppCore` 是所有领域服务的依赖注入容器，持有 `config`、`storage`、`hub`、`providers`、`tasks`、`projects`、`executors`、`proxies`、`skills`（`src/core/context.rs:20`）。CLI 与 Server 入口都必须经由 `AppCore::bootstrap` 组装，不得各自重复接线。

### 主要模块

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| **MCP Server** | `src/adapters/mcp.rs` | Streamable HTTP 工具。检查类只读；`task_start` / `task_status` / `task_cancel` 控制本地 Executor |
| **Web / 管理 API** | `src/adapters/api/*`、`web/` | `/api/*` 管理接口与 Web 控制平面；`/api/*` 仅回环可访问 |
| **OAuth 2.1** | `src/adapters/oauth/*` | 受保护资源/授权服务器元数据、授权码 + PKCE、动态客户端注册、`/mcp` 401 挑战 |
| **CLI** | `src/adapters/cli/*` | 产品入口：`serve` / `start` / `stop` / `restart` / `status` / `workspace` / `doctor` / `skill` / `task` |
| **ProjectHub** | `src/core/projects/*` | 单进程托管多个本地仓库；每个项目一个 `Workspace` 与一个 `TaskRuntime` |
| **TaskRuntime** | `src/core/task/*` | 任务生命周期、进程监督、取消、结果记录 |
| **Executor** | `src/core/executor/*` | 可插拔执行器抽象 + `ExecutorRegistry`；当前仅 OpenCode 适配器 |
| **Agent / AgentContext** | `src/core/agent.rs`、`src/core/skill/agent.rs` | 从 `.agent` 根解析 Rules / Skills，生成每次任务的 `AgentContext` |
| **Skill** | `src/core/skill/*` | SKILL.md 安装、注册、启用/禁用、关键词解析 |
| **Provider** | `src/core/provider/*` | AI Provider / Model 元数据与凭据加密存储、解析（尚未用于实际模型调用） |
| **Proxy** | `src/infra/config/proxy*`、`src/core/executor/proxy.rs` | HTTP/HTTPS/SOCKS5 代理与连通性测试；注入 Executor 子进程 |
| **Storage** | `src/infra/storage/*` | 服务级 SQLite：项目、执行器、任务快照、OAuth、Provider、Proxy、Skill |
| **Service 生命周期** | `src/infra/daemon/*` | 跨平台进程抽象：`start` / `stop` / `restart` / `status`，记录 server PID 并做健康探针 |

## 控制面与管理面

- **MCP（`/mcp`）**：面向 Brain 的数据面，受 OAuth 2.1 / 静态 Bearer 保护。只读检查 + 任务委托，不暴露管理写操作。
- **管理 API（`/api/*`）**：面向 Web 控制平面，仅允许回环地址访问，不参与 Brain 的 MCP Token。
- **Web（`/`）**：静态前端（`rust-embed` 打包 `web/`），调用 `/api/*` 完成项目、执行器、技能、Agent 与设置管理。
- **CLI**：第一控制面；Core 的完整管理能力均可在无 GUI 环境使用。

## 核心原则

1. **CLI / Core 是产品主体**：`serve`、`start`、`stop`、`restart`、`status`、`workspace`、`doctor`、`task` 与 MCP Server 构成完整形态。
2. **Web 是管理控制面**：只做可视化与配置，不承载独立业务逻辑，也不负责启动任务。
3. **SQLite 是任务 / C2C 权威状态**：运行数据（项目、执行器、任务快照、OAuth、Provider、Proxy、Skill）存放于 `~/.agentbridge/agentbridge.db`；启动级配置存放于 `~/.agentbridge/config.toml`。
4. **workspace 不再使用 `.agentbridge/current.c2c`**：任务契约以渲染副本形式写入 `~/.agentbridge/handoff/<task_id>.c2c`（非权威），权威状态在 SQLite。
5. **Agent 配置集中于 `~/.agentbridge/.agent`**：`Agent.yaml`、`Rules/`、`Skills/`、`projects/*.yaml` 与工作区解耦，见 [Agent体系](Agent体系.md)。
6. **Executor 通过抽象与 Registry 解耦**：新增执行器只需实现 `Executor` trait 并注册，核心任务流程无需改动，见 [执行器](执行器.md)。

## 状态与持久化

| 数据 | 介质 |
| --- | --- |
| 启动级配置（host/port/allow_any_host/认证/日志/executor/proxy/security） | `~/.agentbridge/config.toml` |
| 后台服务 PID / 监听地址（生命周期状态） | `~/.agentbridge/service.json` |
| 后台服务 stdout/stderr | `~/.agentbridge/service.log` |
| 项目、执行器、任务/C2C 权威状态、OAuth、Provider、Proxy、Skill | `~/.agentbridge/agentbridge.db`（SQLite） |
| Agent 配置（Agent.yaml / Rules / Skills / projects/*.yaml） | `~/.agentbridge/.agent/` |
| Executor 读取的任务契约（渲染副本，非权威） | `~/.agentbridge/handoff/<task_id>.c2c` |
| 运行中的 Executor 进程号 | `<workspace>/.agentbridge/executor.pid`（与 `service.json` 无关） |

服务是否运行由 `service.json` 中的 PID 存活性与 `/health` 探针判定，**不查询 SQLite**；因此 Service Lifecycle 与 Executor Process Lifecycle 严格分离。

MCP 的 `test_status` / `execution_summary` / `task_status` 通过 `Storage` 读取，因此 CLI、Web 与 Brain 共享同一份事实来源。

## 信任边界

Brain 是远端模型，绝不应获得：

- 任意文件系统访问；
- 通用 shell 工具；
- 写文件工具；
- 可执行文件名（Executor 命令来自本机注册表，而非 MCP 请求）；
- 敏感文件（`.env`、密钥、`~/.ssh` 等）。

Executor 是用户已经信任的本地 Agent。AgentBridge 只把它启动在所选工作区内，并记录结构化结果：

```text
status, summary, exit_code, tests, changed_files, error
```

模型内部推理不会被存储或返回（`<think>` 等会被剥离）。
